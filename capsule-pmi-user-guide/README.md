# Capsule — System Documentation

### Test Documentation • ПМИ • User Guide • Requirements Verification

## 📌 О проекте

Проект подготовки эксплуатационной и испытательной документации
для веб-сервиса бронирования капсульных отелей «Капсула».

Проект является продолжением функционального тестирования
веб-версии сервиса Capsule 2.2.

После выявления функциональных несоответствий была подготовлена
документация, необходимая для проведения испытаний исправленной
версии системы и последующей работы пользователей с сервисом.

## 🎯 Цель проекта

Подготовить документацию для проверки соответствия реализованной
системы требованиям и обеспечить пользователей инструкциями
по работе с основными функциями веб-сервиса.

## 📄 Подготовленная документация

### 1. Программа и методика испытаний

ПМИ содержит порядок проверки функциональных требований
веб-сервиса.

В документе описываются:

- условия проведения испытаний;
- предусловия;
- последовательность действий;
- шаги проверки;
- ожидаемые результаты;
- конечные результаты испытаний.

Особое внимание уделено требованиям, по которым ранее были
выявлены функциональные несоответствия.

### 2. Руководство пользователя

Руководство предназначено для конечных пользователей
веб-сервиса «Капсула».

Документ содержит инструкции по работе с основными функциями:

- просмотр удобств в отеле;
- просмотр инструкции использования капсульного отеля;
- просмотр расположения отелей;
- просмотр стоимости услуг;
- просмотр отзывов;
- просмотр ответов на частые вопросы;
- регистрация;
- авторизация;
- восстановление пароля;
- изменение персональных данных;
- бронирование;
- управление бронированиями;
- отмена бронирования.

Структура руководства и перечисленные функции соответствуют
подготовленному документу пользователя. :contentReference[oaicite:2]{index=2} :contentReference[oaicite:3]{index=3} :contentReference[oaicite:4]{index=4}

### 3. План тестирования

В проект также включён план функционального тестирования,
подготовленный на предыдущем этапе.

Он используется как исходный материал для подготовки ПМИ
и позволяет связать требования, тестовые сценарии и
последующие испытания системы.

## 🧪 ПМИ

Порядок проведения испытаний сформирован на основании
ранее подготовленного тест-плана.

Для каждого проверяемого требования определяются:

**Предусловия → Шаги проверки → Конечный результат**

При описании ожидаемого поведения учитывались не только
результаты предыдущего тестирования, но и предполагаемый
интерфейс исправленной версии системы.

## 👤 Руководство пользователя

Руководство ориентировано на конечного пользователя,
поэтому инструкции сформулированы в виде последовательных
действий.

Например, для бронирования без регистрации пользователь:

1. Нажимает «Забронировать».
2. Указывает дату.
3. Указывает время начала аренды.
4. Выбирает количество часов.
5. Проверяет итоговую стоимость.
6. Выбирает адрес.
7. Вводит контактные данные.
8. Подтверждает согласие с политиками.
9. При необходимости соглашается на создание личного кабинета.
10. Нажимает «Забронировать».

Подробная последовательность приведена в руководстве пользователя.

## ⚠️ Сообщения об ошибках

В руководстве также описаны типовые ошибки пользователя
и способы их устранения.

Для каждой ошибки указаны:

- сообщение системы;
- возможная причина;
- действия пользователя.

Например, для ошибок регистрации описаны проблемы
с именем и фамилией, телефоном, email, паролем и повторным
вводом пароля. :contentReference[oaicite:6]{index=6}

## 🔄 Управление бронированием

Отдельно описаны операции работы с существующими бронированиями:

- просмотр запланированных бронирований;
- отмена бронирования;
- изменение бронирования.

При этом изменение существующего бронирования напрямую
не предусмотрено: пользователю необходимо отменить
существующее бронирование и создать новое. :contentReference[oaicite:7]{index=7}
