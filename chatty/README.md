# Chatty 2.0 — Requirements Specification

### SRS • Requirements Analysis • Use Case • Data Modeling • NFR

## 📌 О проекте

**Chatty 2.0** — веб-приложение для изучения английского языка,
предоставляющее пользователям возможности работы со словарём,
карточками и дополнительными материалами для изучения слов.

В рамках проекта разработана спецификация требований к программному
обеспечению (SRS), описывающая функциональность и требования
к версии 2.0 веб-приложения.

---

## 🎯 Цель проекта

Формализовать требования к новой версии веб-приложения и подготовить
спецификацию, которая может использоваться командой разработки
и тестирования.

Основные задачи:

- определить границы системы;
- описать классы пользователей;
- определить функциональные требования;
- формализовать пользовательские сценарии;
- описать требования к данным;
- определить внешние интерфейсы;
- сформировать нефункциональные требования;
- зафиксировать бизнес-правила и ограничения.

---

## 👥 Пользователи системы

В системе выделены два основных класса пользователей:

- **Ученик** — пользователь, изучающий английский язык;
- **Преподаватель** — пользователь, который проводит обучение,
  формирует домашние задания и оценивает успеваемость учеников.

---

## 🔄 Основная функциональность

### Словарь

- поиск слов;
- просмотр перевода;
- прослушивание произношения;
- просмотр подробной информации;
- просмотр иллюстраций;
- добавление слов в пользовательский словарь;
- удаление слов;
- просмотр пользовательского словаря.

### Карточки

- добавление карточки для изучения;
- удаление карточки;
- запуск режима тренировки;
- просмотр карточек;
- просмотр перевода;
- фиксация результатов «Помню» / «Не помню»;
- переход к следующей карточке.

### Видеопросмотр

- выбор слова для просмотра;
- запуск видеоплеера;
- просмотр видео с контекстным употреблением слова;
- постановка видео на паузу;
- перемотка;
- возврат к словарю;
- обработка недоступности видео;
- обработка слабого интернет-соединения;
- изменение качества видео.

## 📋 Requirements

### Функциональные требования

Функциональные требования описывают работу словаря,
пользовательского словаря, карточек и видеоплеера.

Примеры:

- система должна предоставлять поиск слов в словаре;
- система должна отображать перевод слова;
- система должна предоставлять возможность прослушивания
  произношения;
- пользователь должен иметь возможность добавлять слова
  в свой словарь;
- пользователь должен иметь возможность удалять слова;
- система должна предоставлять режим тренировки;
- система должна сохранять результаты проверки знаний;
- система должна предоставлять видеоплеер для просмотра
  контекстного видео.

## 🔗 Use Case

Для функциональности словаря и видеопросмотра разработаны
варианты использования.

Основные Use Case:

- Найти слово в словаре
- Прослушать озвучку произношения
- Добавить в словарь пользователя
- Просмотреть подробную информацию
- Просмотреть список слов
- Удалить слово
- Посмотреть перевод
- Добавить карточку для изучения
- Удалить карточку
- Проверить знания
- Посмотреть видео
- Поставить видео на паузу
- Перемотать видео вперёд

Для каждого варианта использования описаны предусловия,
триггеры, основной сценарий, гарантии успеха и альтернативные
сценарии.

## 🗄 Модель данных

В проекте разработана логическая модель данных,
включающая сущности и связи, необходимые для работы
со словарём и пользователями.

Основные данные:

- оригинал слова;
- перевод;
- озвучка;
- видео;
- иллюстрация;
- пользователь;
- никнейм;
- роль.

Также подготовлен словарь данных с описанием типов,
ограничений и значений данных.

## 🔌 Внешние интерфейсы

Проработано взаимодействие системы с внешними компонентами.

### Подключаемый словарь

Система должна обращаться к подключаемому словарю
для получения:

- перевода;
- аудиодорожки;
- вариантов правильного написания слова.

### Библиотека видеофайлов

Система обращается к подключаемой библиотеке
для получения видео с контекстным употреблением слова.

### Email

Система отправляет пользователю уведомление
о добавлении нового перевода для слов из пользовательского словаря.

## ⚙️ Нефункциональные требования

### Производительность

Определены требования к:

- количеству пользователей;
- пиковой нагрузке;
- времени загрузки страниц;
- скорости добавления слова;
- времени запуска видео.

Например, веб-страницы должны полностью загружаться
не более чем за 3 секунды при указанной скорости соединения.

### Безопасность

- обязательная авторизация пользователей;
- доступ пользователя только к собственному словарю.

### Доступность

Определены требования к доступности веб-приложения
в различные периоды времени.

### Удобство использования

Определены требования к количеству действий пользователя
для добавления и удаления слов, а также запуска видеоплеера.

## 📐 Ограничения и зависимости

В спецификации зафиксированы ограничения:

- использование PostgreSQL;
- соответствие HTML5;
- работа веб-приложения в определённых браузерах;
- зависимость словаря от подключаемой библиотеки;
- зависимость аудио от доступности аудиофайлов;
- зависимость видеопросмотра от доступности видеофайлов.

---

## 📖 Бизнес-правила

В проекте определены бизнес-правила, регулирующие работу
пользовательского словаря.

Например:

- одно слово нельзя добавить в пользовательский словарь дважды;
- добавить слово в пользовательский словарь может только
  соответствующий пользователь;
- каждое видео должно содержать информацию об источнике и авторе.
