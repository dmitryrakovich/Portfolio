# Nakarabine — SRS & Requirements Analysis

### Software Requirements Specification • Use Case • Functional Requirements • NFR • Data Requirements

## 📌 О проекте

Проект анализа и спецификации требований к веб-приложению
«Накарабине» — интернет-магазину одежды, экипировки и аксессуаров
для активного отдыха.

В рамках проекта разработана спецификация требований к версии 1.0
системы, предназначенная для использования командами разработки
и тестирования.

## 🎯 Цель проекта

Формализовать требования к веб-приложению и описать функциональность
системы в виде структурированной спецификации требований.

## 🔍 Область системы

Система предоставляет пользователю возможность:

- просматривать каталог товаров;
- искать товары;
- фильтровать товары по категориям;
- просматривать информацию о товаре;
- добавлять товары в заказ;
- изменять количество товаров;
- вводить персональные данные;
- указывать адрес доставки;
- выбирать способ оплаты;
- оплачивать заказ картой;
- оплачивать заказ при получении;
- получать подтверждение оформления заказа.

## 📋 Что было проработано

### 1. Общая информация о системе

Определены:

- цель и границы проекта;
- классы пользователей;
- операционная среда;
- ограничения реализации;
- предположения и зависимости.

Для первой версии системы предусмотрен один основной класс
пользователей — покупатель.

### 2. Use Case

Разработаны сценарии взаимодействия пользователя
с веб-приложением.

Основные варианты использования:

- просмотр списка товаров;
- просмотр информации о товаре;
- поиск товара;
- поиск товара по категории;
- оформление заказа;
- ввод данных пользователя;
- ввод контактной информации;
- ввод данных доставки;
- изменение количества товара;
- выбор способа оплаты;
- оплата картой;
- оплата наличными.

### 3. Функциональные требования

Функциональные требования сгруппированы по основным областям
системы:

- каталог товаров;
- заказ товаров;
- данные пользователя;
- доставка;
- оплата;
- уведомления.

Для требований определены основные и альтернативные сценарии
поведения системы.

### 4. Требования к данным

Разработана логическая модель данных и словарь данных.

В модели представлены сущности, связанные с:

- заказами;
- товарами;
- категориями;
- товарами в заказе.

Для атрибутов определены:

- назначение;
- тип данных;
- ограничения и допустимые значения.

### 5. Нефункциональные требования

Определены требования к:

- удобству использования;
- производительности;
- безопасности;
- доступности;
- надёжности.

Например, задано требование полной загрузки веб-страниц
не более чем за 3 секунды при определённой скорости соединения.

### 6. Требования к интерфейсам

Проработаны:

- пользовательские интерфейсы;
- программные интерфейсы;
- коммуникационные интерфейсы.

Предусмотрено взаимодействие с каталогом товаров,
платёжной системой и механизмами отправки уведомлений.

### 7. Бизнес-правила

Определены ограничения бизнес-логики системы.

Примеры:

- заказ должен содержать от 1 до 50 позиций;
- все товары одного заказа доставляются в одно место;
- все товары одного заказа оплачиваются одним способом;
- стоимость заказа рассчитывается на основе цены и количества товаров;
- товар может относиться к одной категории.
